## 1. Executive Summary & Epistemological Role

**StudyLab** is the procedural semantic learning subsystem within StudySourceCore. It is engineered specifically for disciplines that require algorithmic calculation, deduction, and method selection:
- **Mathematics** (Arithmetic, Algebra, Trigonometry, Geometry, Number Systems)
- **Physics** (Kinematics, Dynamics, Energy, Circuits, Optics numericals)
- **Chemistry** (Stoichiometry, Equilibrium ICE tables, Gas laws, pH, Reaction mechanisms)
- **Reasoning** (Syllogisms, Seating arrangements, Matrix puzzles, Coded relations)

### Why StudyLab Exists
Standard flashcards fail catastrophically when applied to procedural knowledge. Prompting a student with "State the formula for incline acceleration" tests passive semantic recall, but fails to assess whether the student can:
1. Recognize when an incline problem involves friction vs. frictionless motion.
2. Resolve forces into normal and parallel coordinate components.
3. Handle sign conventions and unit conversions.
4. Execute arithmetic under time pressure while avoiding common distractor traps.

StudyLab formalizes the complete cognitive pipeline required to transform novices into expert problem solvers.

## 2. Core Invariants of StudyLab

### Invariant 1: `Pattern != Question`
- A **Problem Pattern** represents an abstract schema or family of problems (e.g., `family.math.lcm_hcf.bells_ringing`).
- A **Practice Question** is an authentic, concrete problem instance with specific numbers, phrasing, and exam citations.
- **Rule**: Distinct solvable questions in the source evidence must **NEVER** be collapsed into a single generic template. All distinct questions must be preserved as discrete practice items with unique card anchors.

### Invariant 2: Source-First Practice Hierarchy
Practice questions adhere strictly to an evidence-grounded origin hierarchy:
$$\text{authentic\_pyq} \succ \text{curated\_source} \succ \text{derived\_variant} \succ \text{synthetic\_schema}$$
1. `authentic_pyq`: Real Previous Year Questions extracted from official exam papers (RRB, SSC, etc.).
2. `curated_source`: Practice problems from authorized textbooks (e.g., NCERT exercise problems).
3. `derived_variant`: Isomorphic variations generated by altering numerical parameters within validated domains.
4. `synthetic_schema`: Algorithmic edge cases created to test boundary conditions.

### Invariant 3: Inviolable MCQ Hard Invariant ($\ge 4$ Options)
Every multiple-choice practice item must provide at least 4 distinct, non-empty options with exactly one correct answer and three plausible, error-driven distractors. Truncated 2- or 3-option MCQs trigger an immediate validation failure.

### Invariant 4: `Questions.md` is a Rendered Projection
`Questions/<Chapter>_Questions.md` provides an ergonomic, human-readable reading view for students and teachers. It is **NOT** the canonical semantic store. Canonical practice questions reside strictly in the typed Semantic Learning IR (`Optional/<Chapter>_PracticeQuestions.json`).

## 4. The 4-Stage Scaffolding Pipeline

Every problem family is compiled into four progressive instructional stages:

1. **Stage 1: Worked Example (Schema Acquisition)**
   - Demonstrates the expert thought process from problem reading to final verification.
   - Explicitly displays the Free Body Diagram (Physics), ICE Table (Chemistry), or Factoring Tree (Math).
   - Explains *why* the governing equation was chosen over alternative formulas.

2. **Stage 2: Faded Completion (Guided Practice)**
   - Backward fading: The system provides the complete initial coordinate setup and given values.
   - The student is prompted to perform the intermediate substitution and final calculation.

3. **Stage 3: Independent Practice (Full Active Retrieval)**
   - Presents the authentic PYQ or textbook problem.
   - The student independently extracts parameters, selects the method, and solves.
   - Supported by the 3-Tier Progressive Hint ladder if the student reaches an impasse.

4. **Stage 4: Transfer (Boundary Generalization)**
   - Presents isomorphic problems with altered surface features (e.g., changing an elevator problem into a rocket acceleration problem).
   - Tests boundary conditions and limits to confirm deep structural mastery.

## 5. The 3-Tier Progressive Hint Ladder

When a student encounters an impasse, hints are served sequentially without leaking the final answer:

- **Tier 1: Conceptual Approach (Schema Activation)**
  - Identifies the underlying physical or mathematical law.
  - *Hindi*: "इस प्रश्न में संवेग संरक्षण नियम लागू होगा।"
  - *English*: "Apply the Law of Conservation of Linear Momentum."
- **Tier 2: Governing Method (Tool Identification)**
  - States the specific formula with variable definitions.
  - *Formula*: $m_1 u_1 + m_2 u_2 = (m_1 + m_2) v$
  - *Constraint*: Does not plug in problem parameters.
- **Tier 3: Structural Setup (Near-Complete Scaffold)**
  - Substitutes given values into the formula, leaving the final arithmetic to the student.
- **Terminal Answer Protection**: Under no circumstances may any hint tier (Tier 1, Tier 2, or Tier 3) state the final numerical value (e.g., "$v = 794.4\text{ m/s}$"), final deduced state, or reveal the correct MCQ option key. Intermediate scaffolding (e.g. algebraic setup equation or intermediate first-step operation) is permitted in Tier 3, but terminal answer immunity is strictly enforced.

## 6. Procedural APKG Packaging (Model `1600000004`)

### Dedicated Anki Model Architecture
StudyLab packages do not use standard basic or cloze card models. They compile exclusively into **Model `1600000004` (StudyLab Procedural Anchor)**:

- **Fields (4 Total)**:
  1. `ProceduralPayload`: JSON string containing problem prompt, options, solution DAG, 3-tier hints, and parameter domains.
  2. `TopicTitle`: Chapter or topic designation.
  3. `Domain`: Subject classification (Math, Physics, Chemistry, Reasoning).
  4. `Provenance`: Cryptographic evidence hash and source citation.
- **Template**: The card template dynamically intercepts `ProceduralPayload`, rendering interactive problem-solving interfaces on Anki desktop and mobile.

### SQLite Isolation & Clean Hygiene
- **Strict Isolation**: Model `1600000004` cards live exclusively in `StudyLab/<Chapter>_StudyLab_Procedural.apkg`. They are strictly forbidden from the declarative deck (`<Chapter>_Anki.apkg`).
- **Zero Database Pre-Seeding**: The procedural APKG is completely self-contained and portable. It imports cleanly into a fresh Anki profile without requiring external database pre-seeding.
